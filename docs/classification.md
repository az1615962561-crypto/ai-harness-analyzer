# AI Agent 分类体系

## 核心原则

分类的唯一标准：**这类 Agent 的 Harness 必须解决的、不可绕过的核心工程难题是什么？**

如果两类 Agent 的核心难题相同，就该合并；如果不同，就必须分开——因为这个难题直接决定了它的 Harness 长什么样。

## 五大分类

### 🔧 工程型 Agent — 让 AI 安全地操作真实系统

> 代表：Cursor, Claude Code, Devin, Antigravity

AI 要执行代码、改文件、跑终端命令。**这些操作是不可逆的**。

**Harness 核心构件：**
- 沙箱隔离（限制执行边界）
- 代码理解引擎（让 AI 知道自己在改什么）
- Diff/Checkpoint（改坏了能回退）

**专属分析维度：**
1. 沙箱隔离模型 — 容器/VM/WASM？权限边界？
2. 代码理解引擎 — AST/LSP/语义索引？
3. Diff 与变更管理 — 变更生成、预览、应用、回滚
4. 终端与进程管理 — PTY 复用、长运行进程
5. Checkpoint/回滚 — 状态快照、增量快照

### 📊 数据型 Agent — 自然语言到精准查询的翻译

> 代表：ChatBI, Julius AI, Databricks Assistant

**翻译错了，结果就是错的，而且用户很可能看不出来。**

**Harness 核心构件：**
- NL2SQL Pipeline（意图理解 → SQL 生成 → 校验）
- Schema 感知（让模型理解表结构和业务语义）
- 结果可视化（自动选择正确的图表类型）

**专属分析维度：**
1. NL2SQL Pipeline — 翻译链路设计
2. 数据源适配层 — 多数据库统一接入
3. Schema 感知与发现 — 元数据注入、业务语义增强
4. 查询优化与安全 — SQL 注入防护、行级权限
5. 可视化渲染引擎 — 图表类型自动推荐

### 🧠 知识型 Agent — 从海量知识中找对、引对

> 代表：Perplexity, NotebookLM, Notion AI

**找不到就胡说，找到了不标注来源就不可信。**

**Harness 核心构件：**
- RAG Pipeline（切分 → 嵌入 → 检索 → 重排）
- 引用链管理（答案的每句话关联到原文段落）
- 多文档推理（跨文档综合不矛盾）

**专属分析维度：**
1. RAG Pipeline 设计 — Chunking、Embedding、Reranking
2. 索引与向量存储 — 向量数据库选型、索引结构
3. 引用链管理 — inline citation、段落溯源
4. 多文档推理 — Map-Reduce/Refine/层级摘要
5. 知识更新机制 — 增量索引、时效性打分

### 🎨 创作型 Agent — 多模态生成 + 用户满意的迭代

> 代表：Midjourney, v0.dev, Bolt.new

**生成一次不满意是常态**，用户需要不断调整。

**Harness 核心构件：**
- 多模态生成管线（协调文本/图像/代码多种模型）
- 版本/变体管理（4 宫格选择、历史对比）
- 实时预览（生成了立刻能看到效果）

**专属分析维度：**
1. 多模态生成管线 — 文本/图/代码的协调
2. 版本与变体管理 — 多结果对比选择
3. 实时预览系统 — 生成结果即时预览
4. 风格一致性控制 — 跨生成保持统一风格
5. 模板与组件复用 — 预置模板、组件库

### 🤖 自动化型 Agent — 多步骤工作流的可靠执行

> 代表：AutoGPT, Manus AI, CrewAI, LangGraph

**任何一步失败，整个流程就断了。**

**Harness 核心构件：**
- DAG/状态机引擎（定义和执行任务图）
- 容错与重试（单步失败不崩全链）
- 多 Agent 通信协议（Agent 之间怎么交接工作）

**专属分析维度：**
1. DAG/状态机引擎 — 任务编排执行模型
2. 多 Agent 通信协议 — 角色委派、handoff
3. 容错与重试策略 — 失败恢复、补偿事务
4. 外部系统集成 — OAuth、Webhook、API 适配
5. 触发与调度机制 — 定时/事件/手动触发

## 为什么不单独设「个人型」？

「个人型」是**应用场景标签**而非 Harness 架构类型：

| 产品 | 实际 Harness 类型 | 原因 |
|------|-----------------|------|
| Apple Intelligence | 知识型 | 核心是设备端知识检索 |
| Google Gemini App | 自动化型 | 核心是跨 Google 服务编排 |
| Notion AI | 知识型 | 核心是 Workspace 文档的 RAG |
| Lindy | 自动化型 | 核心是邮件/日程的 Workflow |

> 「个人型」作为标签(Tag)保留，不作为独立分类。
