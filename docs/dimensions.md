## 共性层：9 个通用维度

| # | 维度 | 分析什么 |
|---|------|---------|
| 1 | Agent 编排 | 单/多 Agent？编排模式？规划策略？ |
| 2 | 模型路由 | 用哪些模型？按什么策略路由？成本优化？ |
| 3 | 工具调用链 | 什么工具？怎么注册？执行流程？ |
| 4 | Prompt 工程 | System Prompt 管理？模板策略？ |
| 5 | 上下文工程 | 上下文怎么构建？检索策略？窗口管理？ |
| 6 | 数据流与状态管理 | 数据怎么流转？状态怎么持久化？ |
| 7 | 安全与沙箱 | 权限控制？执行隔离？ |
| 8 | 人机协作模式 | AI 自主度？人在哪里介入？审批机制？ |
| 9 | 扩展性与生态 | 插件系统？MCP？社区生态？ |

## 维度权重矩阵

**权重含义**：分析时投入多少深度。5=重点拆解，1=简单提及。

**权重原则**：哪个维度做不好，这类产品就不能用 → 权重 5

| 维度 | 🔧 工程 | 📊 数据 | 🧠 知识 | 🎨 创作 | 🤖 自动化 |
|------|:---:|:---:|:---:|:---:|:---:|
| Agent 编排 | **5** | 2 | 2 | 3 | **5** |
| 模型路由 | **5** | 4 | 3 | **5** | 3 |
| 工具调用链 | **5** | **5** | 2 | 3 | **5** |
| Prompt 工程 | 4 | **5** | 4 | 4 | 2 |
| 上下文工程 | **5** | 3 | **5** | 2 | 2 |
| 数据流与状态 | 4 | **5** | 3 | 3 | **5** |
| 安全与沙箱 | **5** | 4 | 2 | 2 | 3 |
| 人机协作 | **5** | 4 | 3 | **5** | 2 |
| 扩展性与生态 | **5** | 2 | 3 | 2 | **5** |

### 权重验证举例

- **Cursor（工程型）**：沙箱不好 → 执行代码删用户文件 → 产品死掉。安全与沙箱权重 5 ✓
- **Perplexity（知识型）**：不执行任何用户代码，安全面极小 → 权重 2 ✓
- **ChatBI（数据型）**：Prompt 工程差 → SQL 生成错误 → 给老板看假数据 → 权重 5 ✓
- **Midjourney（创作型）**：人机协作差 → 用户无法精修 → 体验崩溃 → 权重 5 ✓

## 特性层：品类专属维度

### 🔧 工程型
1. 沙箱隔离模型
2. 代码理解引擎
3. Diff 与变更管理
4. 终端与进程管理
5. Checkpoint/回滚

### 📊 数据型
1. NL2SQL Pipeline
2. 数据源适配层
3. Schema 感知与发现
4. 查询优化与安全
5. 可视化渲染引擎

### 🧠 知识型
1. RAG Pipeline 设计
2. 索引与向量存储
3. 引用链管理
4. 多文档推理
5. 知识更新机制

### 🎨 创作型
1. 多模态生成管线
2. 版本与变体管理
3. 实时预览系统
4. 风格一致性控制
5. 模板与组件复用

### 🤖 自动化型
1. DAG/状态机引擎
2. 多 Agent 通信协议
3. 容错与重试策略
4. 外部系统集成
5. 触发与调度机制

## 分类 × 维度 交叉关系

不同品类的 Agent，各维度的重要性权重不同。分析时会根据应用所属分类，自动**加权**各维度：

- 对工程型 Agent 重点拆沙箱和工具链
- 对数据型重点拆 NL2SQL 和数据流
- 对知识型重点拆 RAG 和上下文工程
- 对创作型重点拆多模态管线和人机协作
- 对自动化型重点拆 DAG 引擎和容错机制

避免无差别地每个维度都平均用力。
